# Q3: Exam alert channels

## (a) Class diagram
```
            +-------------------+
            | Channel (abstract)|
            | name              |
            | cost()  <<abstract>>
            | deliver(message)  |
            +-------------------+
              ^     ^      ^       ^
              |     |      |       |
            Sms   Email  WhatsApp  PushNotification

  University ◆--------> Channel   (has a list of channels)
  Message  - - - - - -> Channel   (is delivered by)
```
| Pair | Relationship | Reason |
|---|---|---|
| (i) SmsChannel and Channel | **is-a** | An SMS channel is a kind of channel. |
| (ii) Message and Channel | **has-a / uses** | A message is not a kind of channel; a channel delivers messages. |
| (iii) University and Channel | **has-a** | The university owns a collection of channels. |

## (c) Python
- **Who decides which `cost()` runs, and when?** Python decides **at run time**, from the actual class of each object in the list (dynamic dispatch). `self.cost()` is looked up starting at the object's own class.
- **Is a keyword needed?** No. In Python every method is "virtual" by default.
- **What mistake silently breaks it?** Misspelling the method in a subclass (e.g. `cst`) when the parent has a real, non-abstract `cost()`: the parent's version runs with no error. Declaring `cost` abstract helps, because a subclass that misspells it cannot be instantiated.

**Why it was possible:** the loop depends only on the `Channel` interface, not on concrete classes (polymorphism and the open/closed principle: open for extension, closed for modification).

**When inheritance is the wrong choice:** for roles that change over time, e.g. making `Lecturer` a subclass of `Student`. A student who becomes staff would need a new object, and one person holding two roles cannot be modelled. Composition (a Person *has* roles) is better.
