# Q1: UniCash Wallet

## (a) The failure
**Encapsulation** means a class hides its data and lets outside code change it only through methods that check the rules. **An invariant** is a condition that must always be true for an object.
The old `Wallet` had public fields, so `wallet.balance = -500` skipped every check. The class could not protect its own rules, and the invalid state went live.

Two rules a wallet must always keep:
1. The balance is never negative.
2. The total withdrawn in one day never exceeds LIMIT.

In step 5 Python does not raise an error. `w.balance = -500` creates a new, unrelated attribute `balance`; the real private field (`_Wallet__balance`) stays unchanged. Python's double underscore is name-mangling, so it prevents accidents, not determined misuse.

## (d) Storing money as whole cents
**Well designed (private fields):** only code inside `Wallet` changes (constructor, `deposit`, `withdraw`, `getBalance`, the limit check, and conversion at the edges). All callers keep using the same methods.
**If `balance` were public:** every line in the program that reads or writes `wallet.balance` would have to be found and changed, and any missed line would silently be wrong by a factor of 100.
